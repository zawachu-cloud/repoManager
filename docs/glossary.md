# 名詞表

repoManager 的業務名詞。程式命名、測試名稱、計畫與文件一律用這裡的詞。

> 規則(給 AI):
> - 只收本 repo 專屬的業務名詞;通用程式概念(逾時、錯誤等)與實作細節不收。
> - 定義寫「它是什麼」,一到兩句。
> - zawa 講明或確認過的定義:直接寫。從程式或資料推出來的:寫入並在定義後加「(待確認)」,回報時請 zawa 確認。
> - 對話或程式的用語跟本表不一致時:當場問 zawa 哪個對,定案後更新本表並記進「曾經混用」。
> - 有新詞就當場寫,不累積到最後。

## 名詞

| 詞 | 程式名稱 | 定義 | 避免用 |
|----|---------|------|--------|
| pipeline | `/pipeline` skill | orchestrator 依序派 planner、code、review、doc 完成一項任務的自動化流程。 | |
| orchestrator | `orchestrator` agent | 總架構師角色。負責釐清需求、拆子項目、跟 zawa 確認並整合各階段結果,不自己實作。 | |
| 子項目 | `plan-<子項目>`、`tmp/plan-<子項目>.md` | 任務拆出來的一塊獨立工作,每個子項目有自己的計畫檔,做完能從頭到尾驗證。 | |
| 驗證入口(seam) | | 測試從哪裡進去驗證行為的位置,不用改該處程式就能換掉行為。 | 邊界 |
| 小功能切片 | | 計畫裡依序列出的一小步,貫穿必要的層,做完能獨立驗證。 | |
| 深模組 | | 介面小、背後做很多事的模組。 | |
| 淺模組 | | 介面跟內部一樣複雜、只是轉手的模組。 | |
| 名詞表 | `docs/glossary.md` | 每個 repo 必備的業務名詞表,程式命名與文件用詞以它為準。 | 詞彙表 |

## 關係

- 一項任務在 pipeline 裡拆成多個子項目,每個子項目有多個小功能切片。
- 每個小功能切片在驗證入口寫測試。
