# 找出可改善的程式架構

範圍:$ARGUMENTS(空白代表整個 repo)

部分作法改寫自 mattpocock/skills,授權見同目錄 `NOTICE.md`。

**原則**:本 skill 只產出報告與決策,**不改程式碼**。實作一律交給 `/pipeline`,帶決策摘要當需求。

## 白話名詞

對 zawa 說明時,第一次出現就用下面的白話解釋。

- **深模組**:介面小,背後做很多事。呼叫端只要學一點東西就能用。
- **淺模組**:介面跟內部一樣複雜,只是轉手。呼叫端學了一堆,模組卻沒做多少事。
- **驗證入口(seam)**:可以在不改動該處程式的情況下換掉行為的位置,測試也從這裡進去驗證。
- **deletion test**:想像刪掉這個模組。複雜度消失,代表它多餘。複雜度散到各個呼叫端,代表它有價值。
- 一個驗證入口只有一種實作時,只是多一層轉手。有兩種(例如正式與測試用)才值得留。

報告與對話用這組詞:模組、介面、深度、驗證入口。不混用「元件」「服務」「邊界」。

## 步驟

### 1. 探索(派 plan,opus)

派一個 `plan` subagent(`mode=blocking`)。prompt 帶:

- 範圍($ARGUMENTS 或整個 repo)。
- 報告模板絕對路徑 `~/.kiro/skills/improve-codebase-architecture/report-template.md`。
- 輸出路徑 `tmp/arch-<YYMMDD>.md`。
- 只讀不改程式。

plan 要做:

- 沒指定範圍時,用 `git log --oneline` 與變更頻率找熱點。最近常改的地方優先,加深之後收益最大。
- 讀該 repo 的 `AGENTS.md`、`docs/glossary.md` 與相關 `docs/`,用 repo 既有用語。
- 找候選:
  - 淺模組。
  - 同一個概念散在多處,理解一件事要在很多小模組間跳來跳去。
  - 介面洩漏內部細節,緊密耦合的模組互相越界。
  - 難測試:沒有好的驗證入口,或為了測試抽出純函式,但真正的錯誤藏在呼叫方式裡。
  - 檔案超過 300 行(到 400 行列為優先,500 行是硬上限;barrel、自動產生檔、測試除外)。
- 每個候選做 deletion test,寫出「改了之後呼叫端會變怎樣」、預期好處、風險、改動規模(小/中/大)。
- 不在報告裡設計新介面,那是第 3 步的事。
- 回報只給「摘要」(候選清單,每項一行)與「需要 zawa 決定」(沒有就寫「無」)。

### 2. 選題

依摘要用白話列出候選:編號、一句話好處、規模。附建議先做哪一項,然後停下來等 zawa 選。不要把整份報告讀回 context。

### 3. 追問與設計

針對 zawa 選的那一項:

- 追問方式同 `/pipeline` 第 1 步:能查的不問;每輪編號列出,最多約 5 題;每題附建議答案,寫成「回答 yes 就採用建議」;答案取決於前一題的放到下一輪。
- 追問範圍:限制條件、相依對象、加深後模組的樣子、驗證入口後面放什麼、哪些既有測試會保留。
- 介面有多種可能時,派 2 個 `plan` 並行,各設計一版(design it twice),分別寫進 `tmp/arch-<YYMMDD>-<項目>-a.md` 與 `-b.md`。兩版要差異明顯,例如一版極小化介面,一版以最常見的呼叫端為準。每版寫出:介面(含規則與錯誤情況)、呼叫範例、藏在驗證入口後面的東西、取捨。orchestrator 比較兩版的深度、變更集中程度與驗證入口位置,給出傾向的建議,不丟選單。
- 相依對象分類會影響測試方式:純記憶體運算可直接併模組測;有本機替身(例如記憶體檔案系統)的用替身;自己的遠端服務要定義介面並提供記憶體版;第三方服務用注入的 mock。
- 測試策略是取代而非疊加:加深後在新介面寫測試,淺模組的舊單元測試改刪除。
- 決策寫回 `tmp/arch-<YYMMDD>.md` 該項目的「決策」段。
- 出現新名詞或用語被修正時,問 zawa 後,依 `docs/glossary.md` 開頭規則更新該檔。
- zawa 否決某候選,且理由日後可能再被提出時,問 zawa 後把一兩行理由記進該 repo `docs/`。沒有合適文件時,放 `docs/architecture.md` 的「不做的事」一節。不建 `docs/adr/`。暫時性的理由(例如「現在不想做」)不記。

### 4. 交接

決策清楚後,告訴 zawa 可以用 `/pipeline <決策摘要>` 實作,並附報告路徑。不自動啟動。

## 限制

- 必須在有 subagent 工具的 agent(orchestrator)執行。
- 報告放該 repo 的 `tmp/`,不進版控。
- 不寫機密,不碰 prod 資料。
